# 上線指南 — 後端 v42（一個 GS 搞掂，徹底解決填表後無法登入問題）

## 點解之前「填表後登入就登入唔到」？（問題根因解析）

之前你遇到嘅奇怪現象：
- **填表前**：登入完全正常。
- **填表後**：登入區幹事／地域管理員時，系統會卡住或彈 `伺服器冇回應` / `Cannot read properties of null (reading 'ok')`，完全登入唔到！

### 根本原因
1. 當你填表送出（`submitForm`）時，系統會記錄遞交時間（`createdAt`, `submittedAt`），試算表（Google Sheets）會自動把該欄位格式化並保存為 **日期時間（Date/Time Cell）**。
2. 當你嘗試登入並讀取紀錄（`listForDistrict` / `listForRegion`），後端調用 `SHEET_SUB.getDataRange().getValues()` 從試算表讀出每一行，此時 `createdAt` 等欄位在 JavaScript 記憶體中為 `Date` 物件。
3. **Google Apps Script 的通訊限制**：`google.script.run` 在把後端 JS 物件序列化傳送到前端瀏覽器時，**嚴禁傳輸包含 `Date` 物件或函式的巢狀結構**！只要陣列或物件裡含有任何一個 `Date` 物件，整個通訊呼叫就會在 GAS 伺服器端中斷崩潰，並向前端回傳 `null`（或觸發錯誤）。
4. 因此：
   - 填表前（紀錄為空 `[]`）→ 沒有 `Date` 物件 → 序列化正常 → 可以登入。
   - 填表後（有了紀錄 `[m]`）→ 帶有 `Date` 物件 → GAS 序列化中斷回傳 `null` → **登入儀表板直接崩潰登入唔到**！

## v42 修復重點
1. **API 傳輸層自動標準化**：在 `parseSub(m)` 與 API 回傳前，檢查紀錄內所有的屬性；一旦偵測到 `Date` 物件，自動轉化為標準 `.toISOString()` 字串；null 或 undefined 轉為空字串，確保傳送到前端的 JSON 結構 100% 符合 GAS RPC 序列化規範。
2. **修復「已遞交」錯字**：前端原版存在 `"已遒交"` 錯字，導致與後端的 `ST_SUBMITTED="已遞交"` 不吻合，審核員無法看到「檢核」按鈕，現已全數修正為 `"已遞交"`。
3. **消除 Drive 權限阻塞**：Excel 模板繼續採用「匯出時懶建立」（不在 `setup()` 中強制上載 Drive），確保開網址及登入時極速且不會逾時。
4. **根目錄與 apps-script 同步**：修復了舊版本根目錄 `Code.gs` / `app.html` 與 `apps-script/` 資料夾版本不同步的問題。

## 你只需要做 2 步完成升級

### 步驟 1：更新 Google Apps Script (GAS) 專案入面嘅 `Code.gs`
打開你的 GAS 編輯器（Google Apps Script 專案）：
- 將左欄中的 `Code.gs` 內容全部刪掉。
- 複製本專案中的 `apps-script/Code.gs`（或根目錄 `Code.gs`，二者已同步至 v42）的全部內容，貼入 GAS 中的 `Code.gs`。
- 💾 按儲存（或 `Ctrl + S` / `Cmd + S`）。

> 💡 備註：前端 HTML （v42）已經用 Base64 打包在 `Code.gs` 的 `APP_B64` 常數中，只需更新 `Code.gs` 一個檔案即可搞掂！

### 步驟 2：重新部署（新版本）
- 點擊右上角 **部署 → 管理部署作業**。
- 點擊目前網頁應用程式右上角的 **編輯（鉛筆圖示 ✏️）**。
- **版本** 下拉選單挑選「**新版本**」。
- 點擊 **部署**。
